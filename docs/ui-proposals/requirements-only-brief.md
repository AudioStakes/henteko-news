# 5歳の子どもがスマートフォンで楽しむ言葉ゲームの設計要件

この資料だけを入力として、新しいUIを提案する。
コード、既存画面、画像、過去の会話、ほかの提案は参照しない。
今回は設計提案のみとし、アプリや動くプロトタイプは実装しない。
主な利用者は5歳程度の子どもで、必要に応じて保護者が設定を補助する。
UIのテーマ、構図、世界観、色、書体、表現方法はすべて自由に新しく考える。
次の75項目は設計要件であり、特定の外観を指定するものではない。

## 今回求める体験

- U01：5歳程度の子どもがスマホのタッチ操作で、開始、言葉選び、ニュース完成、繰り返しを楽しめる。楽しさは将来、対象児の反応で確認する。
- U02：既存のUI素材と特徴的な意匠を再利用せず、ゼロから新しいUIを設計する。ゲーム外のアイコン等も含めて統一する。一般的な色や標準書体は自由に使える。
- U03：文字をすべてすらすら読めることを前提にせず、何を選ぶか、次に何をするかを理解できる。補助の表現方法は設計で決める。
- U04：選択が受け付けられたこと、進行、待機が分かる。
- U05：言葉を選ぶ過程と、予想外のニュースが完成する瞬間の両方に楽しさがある。
- U06：音なしでも操作と完成が分かる。音だけを唯一の手掛かりにしない。
- U07：正誤、速さ、失敗による評価を必須にしない。どの候補でも完成し、制限時間や失敗判定で中断しない。
- U08：子どもの遊びと高度な音声設定の目的を見分けやすくする。遊ぶためのURL入力や専門知識は不要。
- U09：操作を急がせる演出や長い装飾待機で繰り返しを妨げない。連打で段階を飛ばさない。

## 遊びの機能

- G01：日本語の言葉を組み合わせ、意外でおかしいニュースを作る。通常の遊びに文章入力は不要。
- G02：登録やログインなしでブラウザーから遊べる。スマホとパソコンで利用できる。
- G03：何をする遊びか理解し、自分の操作で開始できる。開始で前の選択と音声エラーを引き継がない。
- G04：「だれが → いつ → どこで → なにを → どうした」の順で各1つ選ぶ。5種類が揃うまでは完成扱いにしない。
- G05：各段階で語彙から重複のない5候補を無作為に提示する。同じ段階では候補を固定し、新しいゲームで再抽選する。同じ語が再び出ることはある。
- G06：1つ選べば、そのゲーム内で保持して自動で次へ進む。追加の確定操作は不要。設定を開閉しても選択と進行を失わない。
- G07：現在の質問と完成までの進み具合が分かる。表現方法は自由。
- G08：連打や同時操作でも最初の1候補だけを採用して1段階進む。離れた選択状態の遅延処理で勝手に進まない。
- G09：5種類が揃ったら、選んだ言葉の完成ニュースを表示する。長い語も含め、すべて読める。
- G10：完成した同じニュースを何度でも再生できる。再生中は重複起動しない。
- G11：完成後、すぐに次のニュースを作れる。選択を消し、前の音声を止め、最初の種類から始める。

開始、選択、完成は状態であり、それぞれ独立した画面や別ページにする必要はない。

## 言葉と完成文

- W01：5種類、全364語（だれ61、いつ85、どこ59、なに75、どうした84）を扱う。UI変更で語彙を削らない。
- W02：候補用の短い表記と、完成文用の助詞付きの表記を区別する。短い候補ラベルの単純連結で完成文を作らない。
- W03：表示用の表記と読み上げ用の読みを区別し、読みが設定されていれば優先する。
- W04：動作は対応表と読みに基づいて丁寧な過去形へ変換し、完成文末に「！」を付ける。表示と音声は表記が異なっても同じ内容を伝える。
- W05：完成文も「だれが、いつ、どこで、なにを、どうした」の順で、語のまとまりと文意を保つ。
- W06：長い候補や長い語だけを組み合わせた完成文でも全文と主要操作に到達できる。
- W07：語彙の重複、空の表示、余分な空白、空の動作用読みを入れない。日本語順で管理し、各種類8語以上という検証条件を保つ。24文字超は警告でありUIの文字数上限ではない。

## 音声

- S01：最後の選択に続いて完成ニュースを自動読み上げする。未完成文を読まず、音声の成否で完成表示を止めない。
- S02：初回も再生し直す場合も、ニュースとして知らせる導入に続けて5種類を区切って順に読み、内容を省略しない。導入の具体文言は自由。
- S03：音声処理中、利用できない状態、失敗が分かる。文字で遊べることを伝え、同じエラーを複数の自動通知で重ねない。
- S04：音声非対応、通信やモデルの失敗、イベント欠落でも遊びを継続できる。再試行可能な場合は再生できる。
- S05：再スタート、音声方式やモデル設定の変更、画面終了で古い音声を止める。遅れて完了した処理で新しい状態を上書きしない。
- S06：音声の重複起動を抑え、完了、停止、失敗後には操作可能へ戻る。
- S07：タッチやキーボード操作に短い操作音を利用できる。二重に鳴らさず、鳴らなくても操作を継続できる。音色は自由。
- S08：標準はブラウザーの日本語音声。大きなモデルやAPIキーは不要で、標準時にモデルや推論ランタイムを読み込まない。端末差を扱う。
- S09：任意でSupertonicのモデル音声を選び、指定モデルと声でブラウザー内に生成できる。方式を無断で自動切替しない。

## 設定

- C01：音声方式、モデルフォルダー、声のJSONを設定できる。ゲームと開発用の音声確認に同じ設定を使う。
- C02：設定の開閉、保存、取消でゲームの選択、段階、完成内容を失わない。
- C03：保存したときだけ変更を適用する。保存せず閉じる、取消、ダイアログの場合のEscapeで編集を破棄する。初期値へ戻す操作も保存までは未反映。
- C04：同じブラウザーに保存した設定を復元する。不正値は既定値で扱い、保存不可でもその場の利用を妨げない。
- C05：公開相対パス、ルート相対パス、HTTP(S) URLを受け付け前後の空白を除く。空値、HTTP(S)以外のURL、#を拒否し、モデルフォルダーでは?も拒否する。声JSONの?は許容。エラー箇所と理由が分かり、書式妥当性と取得成功を区別する。
- C06：狭い縦画面と低い横画面でも全設定と保存、取消に到達でき、必要ならスクロールできる。

## 操作品質

- A01：小さいスマホ、横向き、タブレット、パソコンでも完走できる。確認する表示範囲には320px幅の縦画面、667×375px横画面、1024×600pxを含む。
- A02：全文と操作への到達を優先し、文字や操作を切らず横にはみ出さない。必要な縦スクロールは許容する。
- A03：候補のタッチ領域は高さ44 CSS px以上を下限にし、文字を欠けさせない。子どもに適した最終寸法と間隔は実際の操作で確認する。
- A04：開始、5回の選択、完成、もう一度までキーボードだけでも操作でき、フォーカスが見える。
- A05：新しい問いや完成へフォーカスを移し、状態変化を伝える。初回や設定操作中にフォーカスを奪わず、前のスクロール位置で次の問いを見失わない。
- A06：設定を重ねる場合は背景を操作できず、閉じたら入口へフォーカスを戻す。入力にラベルがあり、エラーから該当項目へ移れる。
- A07：読みやすい文字サイズとコントラストを確保し、操作状態を判別できる。
- A08：端末のセーフエリアを考慮する。OSの動きを減らす設定で装飾アニメーションを抑えても、選択、進行、完成が分かる。
- A09：音声や装飾画像が失敗しても主要操作を失わず、装飾を待って停止しない。
- A10：パソコンのChromium、Firefox、WebKit、Android Chrome相当、iPhoneとiPadのSafari相当で確認する。エミュレーションと実機確認を区別する。

## 通信とホーム画面

- P01：通常のゲームをブラウザー内で動かし、文章生成サーバーや認証を必須にしない。
- P02：初回オンラインで必要ファイルを保存した後、オフライン再読み込みでも文字のゲームを開始、選択、完成、繰り返しできる。新しい必須素材もオフライン利用を壊さない。
- P03：オフラインと通信復帰を再読み込みなしで表示に反映し、音声等の制限を伝える。
- P04：オフライン保証は文字のゲーム。音声の利用は端末等に依存し、大きなモデルとWASMの事前キャッシュは要求しない。
- P05：ホーム画面へ追加できるPWAを保つ。manifest、192pxと512pxアイコン、512px maskable、ホーム画面用アイコンを用意し、単独表示で縦横操作できる。
- P06：HTML、JS、CSSの版を揃えてキャッシュ更新し、他アプリのキャッシュを消さない。更新反映のため一度タブやアプリを閉じて再度開く方式を基準とする。

## 公開時の条件

- O01：選んだ言葉、完成ニュース、独自識別IDを解析へ送らず、画面録画や広告サービス連携を行わない。
- O02：音声設定の保存と解析を区別し、解析用Cookieや識別localStorageを追加しない。
- O03：解析の遅延や失敗、オフラインでゲームとPWA準備を止めない。本番だけ標準beaconを1回読み込み、開発、E2E、プレビューは計測しない。ゲーム状態を個別PVや独自イベントとして送らない。
- O04：外部通信の説明を実装と一致させ、プライバシー説明を確認できる。
- O05：素材、第三者コード、音声モデルの利用条件を守り、必要な許諾表示と出所を更新する。
- O06：日本語指定、タイトル、説明、OGP、アイコン、manifestの内容を新UIと一致させる。
- O07：HTTPSによる静的配信、ドメイン直下、/words-audio-checkの直接アクセスを維持し、Service Workerを長期固定しない。ローカルではlocalhostを利用できる。
- O08：実装時はnpm run validateと関係するE2Eを通し、古い外観だけを検査するテストは新要件に合わせる。今回は実装やテスト実行をしない。

## 開発者用の機能

これらは子どもが通常の遊びで通過する導線に含めない。

- D01：/words-audio-checkで全語彙を順に再生し、通し番号、総数、種類、現在の語が分かる。音声設定を共有する。
- D02：最初から、続きから、種類先頭から再生し停止できる。再生中の重複開始を抑え、停止や失敗した語から再開し、完走後の再開位置を先頭に戻す。
- D03：debugResult=1とwho/when/where/what/actionのURLクエリで完成内容を指定し、長文等を確認できる。
- D04：音声を変える場合は実モデルの生成テストを保ち、生成成功と子どもにとっての聞きやすさを分けて検証する。

## 設計後の確認

- V01：読みに習熟した子と難しい子、音ありと音なしを組み合わせ、言葉の理解、迷い、誤タップ、選択と完成の反応、再び遊ぶ意欲、必要な補助を観察する。人数と合格基準は今後決める。
- V02：音なし、音声非対応、音声失敗、初回保存後のオフラインで、開始から次ゲームまで進める。
- V03：A01〜A10、C02〜C06を自動確認と実機で確認する。
- V04：実機でニュース冒頭が欠けず、音声と操作音が動き聞きやすい。WAV生成やエミュレーションと区別する。
- V05：要件IDごとに提案の対応を説明できる。既存外観を前提にしない。

## 追加しない機能と設計の自由

- 戻る、選び直し、途中保存、履歴、共有、自由入力、アカウント、ランキング、課金は今回の要件に含めない。
- 5段階、各5候補、1候補のタップで自動進行、全文の結果、再生、もう一度を保つ。
- 候補の行列、レイアウト、画面数、見出しやボタンの文言、導入の具体文言、演出、操作音は自由。
- ドラッグ、スワイプ、長押しなど難しいジェスチャーを完走の必須条件にしない。
- 全364語に専用画像を制作済みという前提は置かない。絵や補助がある案は、その制作範囲と、素材がない語も扱う方針を説明する。
- 音声速度、音高、音量の編集UIや全面的な技術移行を追加しない。

## 案を比較するための共通例

説明用のニュース例は「ねこが／きのう／こうえんで／りんごを／たべました！」とする。
これは表示説明用の仮のデータであり、語彙原本への追加や変更を意味しない。
