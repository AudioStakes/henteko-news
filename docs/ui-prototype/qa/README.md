# HTMLプロトタイプの検証

対象は [単一HTML](../index.html) で、この記録は比較用HTMLの検証結果です。
本番アプリの実装と検証は[アプリへの反映記録](../../ui-implementation.md)を参照してください。
`main` の `130c8f5` を基準に作成しました。

## 確認範囲

PlaywrightでChromiumとWebKitを操作し、次の9項目を検証しています。
通常の記録開始サイズは390×844 CSS pxです。
最後の項目では320×568、390×844、844×390、1280×720へ切り替えます。

1. ロゴ・ひよこ・フォントの読み込みと開始操作
2. 5段階の選択、連打で段階を飛ばさないこと、敬体での完成文
3. 音声準備・読み上げ状態が変わってもキーボードフォーカスを保つこと
4. 処理中でも次のニュースを作れ、古いタイマーで結果画面に戻らないこと
5. 設定の入力エラー、取消、保存、既定値、Escapeとフォーカス復帰
6. 音声エラー・非対応・オフライン表示でも文字の遊びを続けられること
7. 全20状態の表示、長い完成文の文末、横にはみ出さないこと
8. 開発者用8操作の模擬状態と、再生中は停止だけが使えること
9. 小さい画面と横向きでも44px以上のボタンと次の質問に到達できること

[実行フロー](flow.mjs)は録画と同じ実行でアサーションを行います。
初回の検証で、小さい画面の選択後に質問が画面外へ残る問題と、WebKitで設定を閉じた後のフォーカス復帰の問題を確認し、修正しました。
API境界、アクセシビリティ、画像との比較は別のサブエージェントがレビューしています。

## 最終結果

Chromium・WebKitともに9項目すべて成功し、ページのJavaScript例外は0件でした。
録画は両方とも390×844で出力し、ffprobeで再生時間と寸法を検証しています。
録画からフレームを取り出し、完成画面と画面切り替えが実際に映っていることも目視確認しました。
