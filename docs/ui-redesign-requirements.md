# 5歳の子ども向けUI再設計の要件一覧

## この文書の目的と対象

「へんてこニュース」の遊びと必要な機能を保ちながら、5歳の子どもがスマートフォンで楽しく操作できるUIをゼロから考えるための要件を定める。
CodexやChatGPTには、この文書を設計の入力として渡す。
今回は要件のみを整理し、UI案や画面デザインは作成しない。

| 取得元       | `AudioStakes/henteko-news` の `origin/main`                                                                                               |

| 取得状態     | `git fetch origin main` 後、ローカルの `main` を同じコミットへfast-forward済み                                                            |

本書では**継承要件**を、mainの機能と操作上の保証から残す条件とする。
**再設計要件**は、今回の依頼と「5歳の子どもがスマホで楽しめる」という目的を具体化した条件とする。
**現行実装の参考情報**は、現在そうなっているだけで、新しい見た目を固定する条件にはしない。
出典の記号は末尾の「根拠資料」に対応する。

## 今回の再設計で満たす体験

この節は今回の依頼を具体化した再設計要件であり、mainで実現や検証が済んでいるという意味ではない。
判定方法は将来の試作に対する条件である。

| ID  | 要件                                                                                                  | 確認すること                                                                                                                                                                     |
| --- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| U01 | 5歳程度の子どもがスマートフォンのタッチ操作で、開始、言葉の選択、ニュースの完成、繰り返しを楽しめる。 | 対象年齢の子どもが実際に操作し、迷う箇所、楽しむ反応、もう一度遊ぼうとする反応を観察する。楽しさをテストの成功だけで判定しない。                                                 |
| U02 | ひよこなどの既存UI素材と特徴的な意匠を再利用せず、新しいUIをゼロベースで設計する。                    | 現行画面を下敷きにせず、キャラクター、背景、ロゴ画像、装飾、構図を刷新する。ホーム画面用アイコンなどゲーム画面外も含める。一般的な色や標準書体が偶然一致することは制約にしない。 |
| U03 | 文字をすべてすらすら読めることを前提にせず、何を選ぶか、次に何をすればよいかを理解できる。            | 読みの習熟が異なる子どもで確認する。理解を助ける表現方法は設計時に決め、特定の絵、音声、キャラクターを要件として指定しない。                                                     |
| U04 | 選択が受け付けられたことと、次へ進んだことを子どもが認識できる。                                      | 各選択のあとに変化が分かる。待機している間も、反応していないのか処理中なのかを取り違えにくい。                                                                                   |
| U05 | 選ぶ過程と、予想外のニュースが完成する瞬間の両方に楽しさがある。                                      | 完成結果だけを見せて終わらず、選択中も子どもの反応を確認する。具体的な演出、長さ、音色は設計で決める。                                                                           |
| U06 | 音が出ない状態でも、操作と完成を理解して遊べる。                                                      | 端末をミュートにしても、開始から完成、次のゲームまで到達できる。音だけを唯一の操作手掛かりにしない。                                                                             |
| U07 | 正解、不正解、速さ、失敗による評価を遊びの必須条件に加えない。                                        | どの候補を選んでも完成へ進め、制限時間や失敗判定によって中断されない。mainにない採点や競争を前提にしない。                                                                       |
| U08 | 子どもが繰り返し遊ぶ操作と、音声の高度な設定の目的を見分けやすくする。                                | 遊ぶためにモデルのURL入力や専門用語の理解を要求しない。設定を開いた場合も進行を失わずに戻れる。                                                                                  |
| U09 | 操作を急がせる演出や、長い待機で繰り返し遊ぶ流れを妨げない。                                          | 演出中の連打で段階が飛ばない。進行に必要な待機と装飾のための待機を区別し、長さは試作で確認する。                                                                                 |

## 遊びの機能

以下は継承要件である。
「開始」「選択」「完成」は遊びの状態を指し、別々のページや現行と同じ画面数を要求しない。

| ID  | 要件                                                                                | 受け入れ条件                                                                                                                                                 | 根拠       |
| --- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------- |
| G01 | 日本語の言葉を組み合わせ、意外でおかしいニュースを作るゲームとする。                | 通常の遊びで文章入力を必要とせず、用意された言葉を選んで完成できる。                                                                                         | R1、R2     |
| G02 | アカウント登録をせず、ブラウザーから遊べる。                                        | 登録やログインを経由せず、スマートフォンとパソコンで遊びを始められる。                                                                                       | R1         |
| G03 | 何をする遊びかを理解し、自分の操作でゲームを開始できる。                            | 開始前に遊び方を把握できる。開始操作から最初の言葉選びへ進み、前のゲームの選択と音声エラーを引き継がない。                                                   | R2、R5     |
| G04 | 「だれが → いつ → どこで → なにを → どうした」の順に、各種類から1つずつ言葉を選ぶ。 | 5種類すべてを選ぶまでは完成扱いにしない。                                                                                                                    | R2、R3     |
| G05 | 各段階で5つの候補を提示する。                                                       | その種類の語彙から重複なく無作為に抽出する。同じ段階を操作している間に候補が勝手に入れ替わらず、次のゲームでは再抽選する。再抽選でも同じ語が出ることはある。 | R1、R2、R3 |
| G06 | 選択した言葉をそのゲーム内で保持し、自動で次の段階へ進む。                          | 選択後に追加の確定操作を要求しない。設定の開閉や無関係な再描画で選択内容と進行が変わらない。                                                                 | R2、R6     |
| G07 | 現在何を選ぶ段階かと、完成までの進み具合を把握できる。                              | 質問と進行が一致する。進行の見せ方を現行の丸印や配置に固定しない。                                                                                           | R2、R9     |
| G08 | 1回の選択で1段階だけ進む。                                                          | 連打や遷移中の追加入力では最初の1候補だけを採用し、段階を飛ばさない。選択を行う状態から離れた後に、残った遅延処理で進行しない。                              | R2、R3     |
| G09 | 5種類が揃ったら、選んだ言葉から完成ニュースを表示する。                             | 選択と結果の対応が保たれ、すべての語と文末を読める。長い語でも欠けない。                                                                                     | R2、R4、R9 |
| G10 | 完成したニュースを再度読み上げられる。                                              | 同じ完成内容を何度でも再生でき、再生中は重複起動しない。                                                                                                     | R5、R6     |
| G11 | 完成後に、続けて新しいニュースを作れる。                                            | 5種類の選択をすべて消去し、前の音声を止め、最初の種類の選択から次のゲームを始める。                                                                          | R2、R5     |

## 言葉と完成文

語彙そのものと、表示用の表記、音声用の読みの対応を保持する。
語彙を絵に置き換えるなどの表現を検討する場合も、語の区別と完成文の意味を失わないことを要件とする。

| ID  | 要件                                                               | 受け入れ条件                                                                                                                                                               | 根拠   |
| --- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| W01 | mainの5種類の語彙を、新UIでも利用できる。                          | 対象コミットの全364語（だれ61、いつ85、どこ59、なに75、どうした84）を扱える。全語の原本はR3とし、この文書に転記して別管理しない。                                          | R3     |
| W02 | 選択肢で読みやすく省略した表記と、完成文に必要な表記を区別する。   | 現行の選択肢では末尾の「が」「を」「で」を取り除く語がある。完成文では語データの助詞を保持し、短縮した選択肢ラベルを単純に連結しない。                                     | R3、R4 |
| W03 | 表示する表記と音声で読む表記を区別する。                           | 読みが設定された語はその読みを使う。読みがなければ表示用の表記を使う。                                                                                                     | R3、R4 |
| W04 | 「どうした」の選択肢と、完成したニュースの文末を適切に使い分ける。 | 語データの読みと対応表に基づいて丁寧な過去形へ変換し、最後に「！」を付ける。例えば「あつめた」は「あつめました！」となる。完成表示と音声は表記が違っても同じ内容を伝える。 | R3、R4 |
| W05 | 完成文の語順と語のまとまりを保つ。                                 | 「だれが、いつ、どこで、なにを、どうした」の順で伝わり、任意の折り返しや表示の分割によって文意が崩れない。                                                                 | R4     |
| W06 | 既存の長い語や読みの長い語を扱える。                               | 最長クラスの候補、長い語ばかりを組み合わせた完成文でも、全文と主要操作へ到達できる。                                                                                       | R3、R9 |
| W07 | 語彙データの検証を維持する。                                       | 種類の中で重複させず、空の表示語、前後の余分な空白、空の動作用読み上げ表現を入れない。日本語順で管理し、各種類8語以上という現行の検証条件を満たす。                        | R17    |

## 読み上げと操作音

| ID  | 要件                                                                      | 受け入れ条件                                                                                                                                                   | 根拠        |
| --- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| S01 | 最後の言葉の選択に続けて、完成したニュースを読み上げる。                  | 未完成の内容を読み上げず、最後に選んだ語も含めて読む。音声開始の成否で完成結果の表示を妨げない。                                                               | R2、R5      |
| S02 | 初回と再生し直す場合の両方で、ニュース全体を伝える。                      | ニュースとして知らせる導入に続き、5種類の間に区切りを入れて順番に読み、省略や前回内容の混入がない。                                                            | R4、R5      |
| S03 | 音声の処理中、利用できない状態、失敗を利用者が理解できる。                | 操作可能な状態と待機中を見分けられ、音声がなくても文字で遊べることを伝える。エラー時に状態文とエラー文を重ねて自動通知しない。表示の場所や文言は再設計できる。 | R5、R6      |
| S04 | 音声に失敗してもゲームを継続できる。                                      | 音声非対応、ネットワークやモデルの失敗、再生イベントの欠落で操作不能にならず、文字で完成と次のゲームへ進める。再試行できる場合は再生し直せる。                 | R5、R6      |
| S05 | 古い音声と新しいゲームの音声を混在させない。                              | 再スタート、音声方式やモデル指定の変更、画面の終了後は古い要求を取り消す。遅れて終わった処理が再生や表示を上書きしない。                                       | R5、R6      |
| S06 | 音声処理を重ねて起動しない。                                              | 読み上げ中の再生連打を抑え、完了、停止、失敗後には操作できる状態へ戻る。                                                                                       | R5、R6      |
| S07 | 操作に対する短い効果音を利用できる。                                      | タッチとキーボード等の操作に対応し、同じ操作で音を二重に鳴らさない。音が鳴らなくても操作は成功する。音色や高さは引き継ぎ条件にしない。                         | R6          |
| S08 | 標準ではブラウザーの日本語音声を利用し、音声モデルやAPIキーなしで遊べる。 | 標準設定で大きなモデルや推論ランタイムを読み込まず、日本語の声が利用できれば優先する。端末による可否を正しく扱う。                                             | R1、R6、R13 |
| S09 | 任意でモデル音声を選択できる。                                            | 既存のSupertonic方式を選び、設定したモデルと声でブラウザー内に音声を生成できる。方式を無断で自動切り替えしない。                                               | R6、R7、R13 |

## 音声設定

設定の入口や編集の見せ方は再設計できる。
以下は設定機能の継承条件であり、子どもに高度な設定を済ませさせる条件ではない。

| ID  | 要件                                                               | 受け入れ条件                                                                                                                                                                                                                                        | 根拠       |
| --- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| C01 | 音声方式、モデルのフォルダー、声のJSONファイルを設定できる。       | 標準のブラウザー音声と任意のモデル音声を選べる。現在のゲームと音声確認機能に同じ設定を反映する。                                                                                                                                                    | R6、R7、R8 |
| C02 | 設定を編集している間もゲームの状態を保持する。                     | 開く前の選択、段階、完成内容を失わず、保存や取消の後に遊びへ戻れる。                                                                                                                                                                                | R7         |
| C03 | 保存したときだけ変更を適用する。                                   | 取消や保存せずに閉じる操作では、未保存の編集を捨てる。ダイアログとして表示する場合はEscapeも同様とする。初期値へ戻す操作も、保存するまでは適用しない。                                                                                              | R7         |
| C04 | 同じブラウザーで保存済み設定を復元する。                           | 再読み込み後も方式とモデル指定を保持する。不正な保存値は既定値で扱い、保存機能が使えない場合もその場の利用を妨げない。                                                                                                                              | R7         |
| C05 | モデルの指定値を保存前に検証する。                                 | 公開済みの相対パス、`/`から始まるパス、HTTP(S) URLを受け付け、前後の空白を除く。空値、HTTP(S)以外のURL、`#`を拒否し、モデルフォルダーでは`?`も拒否する。声のJSONの`?`は許容する。エラーの項目と理由が分かる。書式の検証と実際の取得成功を区別する。 | R7         |
| C06 | 狭い縦画面と低い横画面でも、すべての項目と保存、取消へ到達できる。 | 内容が多い場合はスクロールでき、エラー表示によって操作が画面外に閉じ込められない。                                                                                                                                                                  | R7、R9     |

## スマートフォンでの操作とアクセシビリティ

この節では、現行の操作上の保証を継承する。
数値はmainの回帰確認の基準であり、5歳の子どもにとって最適と実証された値ではない。

| ID  | 要件                                                                   | 受け入れ条件                                                                                                                                                            | 根拠       |
| --- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| A01 | 小さいスマートフォン、横向き、タブレット、パソコンで遊びを完了できる。 | 少なくとも現行のE2E対象の表示範囲で、開始から完成と繰り返しまで操作できる。対象例は幅320pxの縦画面、667×375pxの横画面、1024×600pxの低い画面。                           | R9、R14    |
| A02 | 全文と操作への到達を、見た目の収まりより優先する。                     | 文字や操作が切れず、横方向にはみ出さない。必要な縦スクロールを禁止しない。長い候補と完成文でも読める。                                                                  | R9         |
| A03 | 選択肢に十分なタッチ領域を確保する。                                   | 現行の可用性テストの下限である高さ44 CSS pxを下回らず、文字が水平にも垂直にも欠けない。最終的な大きさと間隔は子どもの操作で確認する。                                   | R9         |
| A04 | キーボードでも主要な遊びを一巡できる。                                 | 開始、5回の選択、完成、もう一度まで操作でき、フォーカス位置を目で確認できる。                                                                                           | R9         |
| A05 | 状態が切り替わったことを支援技術とキーボード利用者に伝える。           | 新しい質問や完成内容へ適切にフォーカスを移す。初回表示や設定の操作中に既存のフォーカスを奪わない。前の画面のスクロール位置によって次の問いを見失わない。                | R2、R9     |
| A06 | 設定を重ねて表示する場合、操作とフォーカスを正しく管理する。           | 背景を誤操作できず、設定内で必要な操作ができ、閉じた後は元の入口へ戻る。入力にラベルがあり、エラーを認識して該当項目へ移れる。                                          | R7、R9     |
| A07 | 文字、主要な操作、操作状態を判別しやすくする。                         | 読める文字サイズと背景とのコントラストを確保し、フォーカスを消さない。新しい配色は再評価し、現mainの色を合格条件にしない。                                              | R9、R15    |
| A08 | 端末の画面端や動きを減らす設定に配慮する。                             | セーフエリアで操作が隠れず、OSの「動きを減らす」設定では装飾アニメーションを抑える。動きを減らしても選択、進行、完成が分かる。                                          | R9         |
| A09 | 音声や装飾画像の不具合で主要な操作を失わない。                         | 音声なしでも進行でき、装飾の表示を待って操作が止まらない。                                                                                                              | R1、R2、R6 |
| A10 | 現行のブラウザー検証範囲で遊べる。                                     | パソコンのChromium、Firefox、WebKitと、Android Chrome相当、iPhoneとiPadのSafari相当で主要操作を確認する。現行の自動検証はエミュレーションであり、実機確認とは区別する。 | R14、R15   |

## プライバシーと公開時の条件

| ID  | 要件                                                   | 受け入れ条件                                                                                                                                                                                                                       | 根拠          |

## レビュー記録

ゲームと語彙、音声と設定、操作品質と配布の3分野をサブエージェントが独立に調査した。
別のサブエージェントが5歳向けの目的と、既存実装を設計制約にしすぎない表現を確認した。

| 回    | 指摘と修正                                                                                                                                                                                                                                                                                                                             | 結果                                               |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 第1回 | ゲーム内の保持と端末への保存を区別。設定に使えるパスの条件を具体化。完成表示と音声の表記差を許容。画面録画と広告連携を行わない条件、OSの動き抑制、対象ブラウザーを明記。既存素材の刷新と汎用的な色や書体の自由を区別。Escapeの取消をダイアログの場合へ限定。音声導入の具体文言を参考へ移し、読字差と音の有無を組み合わせた確認を追加。 | 指摘を反映して修正した。                           |
| 第2回 | 同じ4分野で修正文書を再レビューし、機能の欠落、誤記、mainの事実と追加要件の混同、既存外観の過度な固定を確認。                                                                                                                                                                                                                          | 各担当から重大な問題が残っていないことを確認した。 |

このレビューは要件と表現のレビューであり、子どもによる操作や実機の音声品質の実証は含まない。
